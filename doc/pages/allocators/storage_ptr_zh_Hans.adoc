== `存储指针`

[#author .author]#本库中的变长容器均使用动态分配内存# +
[#revdate]#来存储其内容。调用方可通过在特定构造函数和函数参数列表中指定#

[[content]]
[[preamble]]
link:#ref_storage_ptr[++[++ref++_++storage++_++ptr++]++]
来掌控分配策略。link:#ref_storage_ptr[++[++ref++_++storage++_++ptr++]++]
具有以下特性：

* 存储指针始终指向一个有效的、经过类型擦除的
++{++ref++_++memory++_++resource}。
* 默认构造的存储指针引用的是link:#default_memory_resource[默认资源]——一个由实现定义的实例，该实例始终使用等效于全局
operator new 和 operator delete 的方式。
* 由 ++{++ref++_++memory++_++resource} 或
++{++ref++_++polymorphic++_++allocator}
构造的存储指针不获取所有权；调用方需确保资源生命周期持续至不再被引用为止。
* 从
link:#ref_make_shared_resource[++[++ref++_++make++_++shared++_++resource++]++]
获取的存储指针将获得内存资源的共享所有权；资源生命周期将延长至该存储指针的所有副本均被销毁为止。
* 存储指针会在类型擦除资源前记住
link:#ref_is_deallocate_trivial[++[++ref++_++is++_++deallocate++_++trivial++]++]
的值，从而允许在运行时查询该值。

[[_default_memory_resource]]
=== 默认内存资源

默认内存资源使用全局 `operator new` 和 `operator delete`
分配内存。此资源不进行引用计数且具有非平凡的释放函数。所有默认构造的
link:#ref_storage_ptr[++[++ref++_++storage++_++ptr++]++]
对象均引用同一内存资源：

[source,highlight]
----
tmpeo_0ch37.adoc 中的未解析指令 - include::../../../test/doc_storage_ptr.cpp[tag=doc_storage_ptr_1,indent=0]
----

默认构造的库容器使用默认内存资源：

[source,highlight]
----
tmpeo_0ch37.adoc 中的未解析指令 - include::../../../test/doc_storage_ptr.cpp[tag=doc_storage_ptr_2,indent=0]
----

默认内存资源非常适合常规使用场景。它在解析时提供合理性能，并在修改容器内容时保持保守的内存使用策略。

[width="100%",cols="50%,50%",]
|===
a|
注意

|此内存资源不保证与
`boost::container::pmr::get++_++default++_++resource`
的结果相同，也无法通过
`boost::container::pmr::set++_++default++_++resource` 更改。
|===

[[_monotonic_resource]]
=== 单调资源

考虑解析期间的内存分配模式：当遇到数组、对象或字符串时，解析器会在其临时存储区域累积元素。当所有元素已知后，构造值时会向资源请求单次内存分配。因此，解析过程仅以最终尺寸分配和构造容器。内存不会重新分配，即内存缓冲区永远不需要通过分配新的更大缓冲区并释放先前缓冲区来实现增长。

link:#ref_monotonic_resource[++[++ref++_++monotonic++_++resource++]++]
通过内部分配递增的大块全局内存，并将这些内存块分割成较小片段以满足分配请求，从而优化此内存分配模式。它具有平凡的释放函数。单调资源在销毁前实际上不会释放内存。因此，它非常适用于解析
JSON 后检查结果值但不进行修改的场景。

构造值时使用的资源可在调用 link:#ref_parse[++[++ref++_++parse++]++]
时指定，如下所示：

[source,highlight]
----
tmpeo_0ch37.adoc 中的未解析指令 - include::../../../test/doc_storage_ptr.cpp[tag=doc_storage_ptr_3,indent=0]
----

或解析为具有内存资源共享所有权的值：

[source,highlight]
----
tmpeo_0ch37.adoc 中的未解析指令 - include::../../../test/doc_storage_ptr.cpp[tag=doc_storage_ptr_4,indent=0]
----

单调资源可选择构造时使用初始缓冲区（在转向堆之前）。这允许调用方使用栈空间，并为大多数解析的
JSON 避免动态分配，若输入 JSON
大于平均值则回退到堆的动态分配，如下所示：

[source,highlight]
----
tmpeo_0ch37.adoc 中的未解析指令 - include::../../../test/doc_storage_ptr.cpp[tag=doc_storage_ptr_5,indent=0]
----

[[_static_resource]]
=== 静态资源

link:#ref_static_resource[++[++ref++_++static++_++resource++]++]

[[_null_resource]]
=== 空资源

函数
link:#ref_get_null_resource[++[++ref++_++get++_++null++_++resource++]++]
返回空资源的全局实例。该资源提供简单不变式：所有分配调用均会抛出
`std::bad++_++alloc`
异常。空资源实例可用于确保解析过程永不执行堆分配。后续章节将对此进行详细探讨。

[[_allocator_propagation]]
=== 分配器传播

容器
link:#ref_array[++[++ref++_++array++]++]、link:#ref_object[++[++ref++_++object++]++]
和 link:#ref_value[++[++ref++_++value++]++]
均将其构造时使用的内存资源传播至子元素：

[source,highlight]
----
tmpeo_0ch37.adoc 中的未解析指令 - include::../../../test/doc_storage_ptr.cpp[tag=doc_storage_ptr_7,indent=0]
----

此传播行为具有递归性，容器内的所有容器均将传播该资源。容器一旦构造完成，其内存资源便不可更改。

[[_resource_lifetime]]
=== 资源生命周期

需注意 link:#ref_storage_ptr[++[++ref++_++storage++_++ptr++]++]
同时支持共享所有权和引用生命周期模型。通过内存资源指针构造不会转移所有权：

[source,highlight]
----
tmpeo_0ch37.adoc 中的未解析指令 - include::../../../test/doc_storage_ptr.cpp[tag=doc_storage_ptr_8,indent=0]
----

以此方式使用内存资源时（包括通过 ++{++ref++_++polymorphic++_++allocator}
构造存储指针或容器的情况），调用方必须确保资源生命周期持续至所有变量不再引用该资源为止；否则可能导致未定义行为。

共享所有权通过函数
link:#ref_make_shared_resource[++[++ref++_++make++_++shared++_++resource++]++]
实现，该函数使用动态内存分配创建新的引用计数内存资源，并将其作为
link:#ref_storage_ptr[++[++ref++_++storage++_++ptr++]++] 返回：

[source,highlight]
----
tmpeo_0ch37.adoc 中的未解析指令 - include::../../../test/doc_storage_ptr.cpp[tag=doc_storage_ptr_9,indent=0]
----

以此方式构造存储指针时，所引用内存资源的生命周期将延长至所有引用它的变量均被销毁为止。
