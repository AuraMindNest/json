= 转换自定义指南
由于选项众多，可能难以选择最适合您类型的转换自定义方式。本节将讨论这些选项，并建议在何种情况下选择何种选项。

首要建议是使用库提供的转换之一，而非提供自定义转换，除非生成的格式不符合要求。如果库推导出错误的转换类别，您可以通过特化相关特征以继承自 `std::false_type` 来退出。

如果库提供的转换适合您，您可以选择使用直接转换。这也会要求您的许多类型具有默认可构造性。

接下来要考虑的是，您的转换是供内部使用，还是供团队外部用户使用。如果用户是外部的，则最终将由他们决定在何种条件下使用这些转换。相反，对于内部库和应用程序，您拥有对使用条件的完全控制权。

如果您的用户是外部的，则由他们而非您决定抛出异常是否可接受。因此，在这种情况下，最好使用非抛出的 `tag_invoke` 重载。此外，对于自定义复合类型的转换，始终使用带有两个上下文参数的 `tag_invoke` 重载。这将允许正确地将上下文传播到复合类型的元素，同时也允许传播元素转换中的异常。

最后值得一提的是，由于能够提供对 JSON 容器的转换而无需二进制依赖该库，您不必将此类依赖强加给用户。这对于与 Boost.JSON 的互操作仅是辅助功能的库尤其重要。
